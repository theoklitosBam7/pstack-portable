# Research: per-subagent reasoning effort controls

This is a snapshot of sources checked on 2 November 2026. Harness interfaces can change; check the current sources before using these findings to change an adapter. “Per-subagent” means a setting that affects the child agent’s model-side reasoning level, rather than only its prompt, tools, output visibility, turn limit, or the parent model. Availability and names of effort levels depend on the selected model.

## Answer

The strongest documented direct controls are in Claude Code, GitHub Copilot CLI, Cursor, Factory Droid, the local `tb-pi-package` Pi extension, and OpenCode’s agent configuration. Goose and Amp document parent/default inheritance without a documented effort override per child. Crush lets agent roles select configured `large`/`small` model slots, whose model settings can include effort; its docs and config types do not show a direct per-call effort override.

## Contradictions

- **Claude Code changed over time.** Older third-party mirrors and issue reports say subagents had no effort field or inherited only the parent’s extended-thinking toggle. The current first-party docs list `effort` frontmatter and per-invocation `effort`, with version requirements. Current first-party docs are stronger and describe newer behavior. [Current Claude Code docs](https://code.claude.com/docs/en/sub-agents)
- **Goose docs differ by page/version.** The current upstream repository docs state `GOOSE_SUBAGENT_MODEL` / `GOOSE_SUBAGENT_PROVIDER` and recipe precedence; older live docs list these as well but do not add an effort control. No first-party evidence found for a per-subagent effort field.
- **Crush effort terms are not uniform.** Current upstream config supports selected model `reasoning_effort` levels `low/medium/high` for compatible OpenAI models and an Anthropic `think` boolean. This does not establish arbitrary per-agent `low/medium/high` effort or dynamic per-call changes.

## Missing evidence

- **Cursor:** Whether the Task tool accepts an invocation-specific reasoning option beyond naming a model.
- **OpenCode:** Whether an omitted per-agent provider effort inherits the parent effort in all providers and versions.
- **Goose:** Whether child recipe settings can pass provider-specific effort fields despite no first-party subagent effort field being documented.
- **Crush:** Whether the `task` tool supports per-call model or effort overrides in current builds; current docs/config type show no effort parameter.
- **Amp:** Whether a plugin’s `REASONING_EFFORT` can be set independently for Task subagents.
