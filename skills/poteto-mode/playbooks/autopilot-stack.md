### Autopilot-stack

**You own the stack, never the landing. Build and verify the queue with full autonomy, then hand the operator verified PRs to review and land.** The sibling of **Autopilot-full**.

1. **Run the owner loop with stack topology owned by the root.** Resolve the forge once per `../references/forge.md` and use that choice for every PR operation. One owner agent per PR, spawned through the harness, owns its change end to end: build, first push, a ready PR opened before self-proof, self-proof (gates, CI, receipts), skeptical Bugbot triage per `../references/bugbot-triage.md`, a slop-strip with `deslop` when that skill is installed, `/no-comments` (the **no-comments** skill), and babysit to green per `playbooks/babysit.md`. Owners parallelize when the work is self-contained. Within about 15 minutes, every owner starts a `decisions.tsv` trail per the **show-me-your-work** skill, pushes its first branch snapshot, and opens the PR ready, never draft. After that, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). Keep the trail uncommitted where the root and a replacement can access it, and return it in the report. Whoever spawns a subagent records it in `children.tsv` per Autopilot-full step 2. Run the pre-review checks on the committed head as that step requires.
2. **Audit on a real loop.** The root runs an audit tick every hour using the wake or scheduling operation documented by the harness. If the adapter has no timed wake, follow its documented fallback, such as tmux for a long local run, and state that hourly audits cannot be guaranteed. Never claim an unavailable cadence. At each tick, re-read this playbook from trunk with `git show origin/main:skills/poteto-mode/playbooks/autopilot-stack.md` and audit the operation against it. Fix drift during that tick. Probe each owner with a generic liveness or status check. Count only side effects as progress: commits, pushes, PR or check deltas, and store reports. Treat a lane that passes its expected runtime without a side effect as stuck. Stand it down and dispatch a replacement at once. Do not wait for a polite return. Apply the stuck test and replacement rules to owners and all subagents, collect their trails, and end the tick per Autopilot-full step 6.
3. **Hold the operator gates.** State-then-wait, so a request to state the plan is not a go. On the operator's stop, every owner takes an immediate zero-writes hold.
4. **Verify each round.** The owner reports its code-ready head SHA once the shipped code is final, and STACK-READY with the exact head SHA when its loop is green. The root verifies each round per Autopilot-full step 4, with STACK-READY in place of merge-ready. Nothing enters the stack unverified.
5. **Stop at a clean verdict, never ship.** No owner merges, arms auto-merge, or closes. Hand each verified, green PR to the operator. Stack only a PR that builds on another PR; independent PRs target trunk.
6. **Single writer on topology, parallel writers on builds.** Owners push only their own branches and report the tip, current base, and intended parent. The root is the only topology writer. In place of Autopilot-full step 2's rebase onto trunk, rebase each dependent PR onto its parent and each stack root or independent PR onto trunk. For a dependent PR, fetch its parent, rebase onto that exact tip, push with `--force-with-lease` after an `ls-remote` check, and set its PR base to the parent branch through the resolved forge. The root of each stack targets trunk.
7. **Absorb drift at the root, then re-verify what moved.** The root fetches current trunk and rebases each stack from bottom to top. Each dependent PR rebases onto its parent branch; each stack root and independent PR rebases onto trunk. When a rebase surfaces conflicts in an owner's files, that owner fixes its own slice and the root pushes the result. A new head on a lower PR requires restacking the PRs above it. Rewritten heads void verdicts at the old SHAs. Apply the patch-id rule in `playbooks/shipping.md` at each verdict SHA. Anything that is no longer valid goes back through this playbook's step 4 before delivery. Re-run mergeability and CI after every rewritten push even when the patch-id is unchanged. The countersign rule is unchanged from Autopilot-full. A change that loosens a gate needs the root's fresh countersign. Absorbing drift of landed values is not a raise.
8. **Deliver the PRs.** Hand over each verified PR with its verdict in the PR body or a comment. The operator reviews and lands them. After handoff, nobody pushes without the operator's go.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

Each audit tick prompt names this playbook so the no-merge rule remains in force.

**Reply:** each PR's link and verdict, and anything parked or excluded with the reason.
